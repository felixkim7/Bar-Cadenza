- Design: N daemon worker threads (default 2) take (request, cancel_event) from a job queue and put plain (request_id, value, error) tuples on a result queue. The main thread calls poll() once per frame with a bounded drain (8 results). The main thread alone owns the pending table. Requests carry request_id, encounter_id, revision, kind and a caller-prepared immutable payload. Guarantees: one in-flight request per (encounter, kind); at most max_pending (8) in flight; deadline from submit (default 20 s; 2 s in the experiment) produces exactly one "timeout" result, and the late value is dropped; cancelled requests never deliver; results whose encounter is closed or whose revision moved on are dropped as stale; provider exceptions become error data ("Type: message"), never dialogue text. shutdown() cancels all and joins with a time limit. Daemon threads mean even a provider that ignores cancellation cannot keep the process alive (ThreadPoolExecutor was rejected for this reason: it joins workers at interpreter exit). Retry/backoff is deliberately left to T026.
