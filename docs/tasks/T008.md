- Behavior:
  - **Manifest** (`assets/manifest.json`, validated with pydantic). Each asset records:
    - a stable ASCII `asset_id`;
    - its file, relative to `assets/`;
    - kind and draw layer;
    - logical display size, a fractional anchor and an optional hit region;
    - state, required flag, source, license and approval.
  - **Scenes** in the manifest place IDs at logical points. A placement can override the layer, e.g. a glass held behind the counter.
  - **Rejected manifests:** a bad manifest raises `AssetError` naming the file and record path (e.g. `assets.0.layer`). Rejected cases:
    - duplicate IDs;
    - unknown scene references;
    - paths outside `assets/` (so `references/` can never be loaded), backslashes, unsupported formats;
    - hit regions outside the display size;
    - unknown layers, non-ASCII IDs, empty license.
  - **AssetStore:**
    - Loads each image once (`convert_alpha`), scaled to its display size, and warns once if that stretches the aspect.
    - Draws a scene back to front by layer (room → midground → customer → counter → props → effects → ui), keeping scene order within a layer.
    - `hit_test` returns the topmost interactive item.
    - A missing or unreadable optional image becomes an opaque, hatched, code-drawn placeholder labelled `missing: <id>`, plus one logged diagnostic naming the ID and path.
    - A missing required image raises `AssetError` naming both.
  - **Test window:** `uv run python -m bar_cadenza.app.asset_experiment [--seconds S] [--verify-pointer]` shows the `t008_layer_test` scene (room, patron, counter, jigger), outlines the hovered item, prints clicks and lists diagnostics on screen.
